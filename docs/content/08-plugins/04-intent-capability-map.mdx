<WarningAlert title="Experimental">
This API can change between minor releases while it settles. See [Experimental API](/latest/plugins/experimental-api).
</WarningAlert>

[TanStack Intent](https://www.npmjs.com/package/@tanstack/intent) ships skills (`SKILL.md` files) in packages and validates them. This table maps each behavior of that validation to the Kiira extension point that covers it, so a plugin can replace a bespoke validator.

Each row has a test in [`packages/core/tests/intent-capability.test.ts`](https://github.com/AlemTuzlak/kiira/blob/main/packages/core/tests/intent-capability.test.ts) that builds the behavior from a small inline plugin.

| Intent behavior | Extension point |
| --- | --- |
| Discovery: at the workspace root, `skills/` plus each workspace package's `skills/`; otherwise the package's `skills/`; every nested `SKILL.md`; nothing found means exit 0 | preset `include(project)` + `allowEmpty` |
| Frontmatter errors: missing/invalid block; YAML errors; not a map; `metadata` not a map; top-level vs `metadata` conflicts; `name`/`description` required; name ≤64 chars, no `/`, equals parent folder, matches `^[a-z0-9]+(?:-[a-z0-9]+)*$`; non-spec scalar keys; `metadata` values strings; description ≤1024; `type: framework` requires `requires` | document rule + `frontmatter.raw` |
| Spec warnings: `license`, `compatibility` (≤500), `allowed-tools` types | document rule, warn |
| 500-line limit | `max-lines` or a document rule |
| Fence languages ts, tsx, typescript, js, jsx, javascript only (JS/JSX via checkJs) | preset/override `codeFenceLanguages` |
| Fixed compiler options ignoring the tsconfig | TS hook `replaceTsconfig` + `compilerOptions` |
| Package owns the library but has no type entry: `no type entry found for <library> in <dir>` | project rule or document rule + `project.isTracked` |
| Library self-mapping to git-tracked entry or src fallbacks; workspace package paths | TS hook `paths` + `project.isTracked` |
| Ignored TS codes 1375, 2304, 2318, 2503, 2552, 2580–2584, 2591–2593, 2602, 2686, 2688, 7006, 7026, 7031, 17004, 18004; TS2307/2792 only for library specifiers | TS hook `filterDiagnostic` |
| `@deprecated` named imports from the library | `deprecated-import` with `packages`, or a program rule |
| Inline relative links outside fences to a missing file | `broken-link` or a document rule |
| `skills/_artifacts` required files present, non-empty, valid YAML; package.json warnings | project rule reporting on any file |
| Frontmatter repair (rename `name`, move keys under `metadata`; round-trip safe; CRLF kept; atomic) | document rule `edits` fix + safe writer |
| `--check` (pending fixes fail) | default check behavior (a fixable diagnostic at error severity fails the run) |
| `repair --patch` | `--fix --dry-run` |
| BEFORE/AFTER split into separate fences | document rule `edits` fix |
| `--github-summary` | `github` reporter step summary |
| `--set-version` | rule option + `edits` fix |

Kiira does not parse YAML. The rules that need it read `frontmatter.raw` as text or bring a YAML parser of their own. See [Writing a plugin](/latest/plugins/writing-a-plugin) for each extension point.
