## Running a check from code

`check()` does what `kiira check` does and returns the result instead of printing it. Install `typescript` 5 or newer next to `kiira-core`, and `jiti` if your config is a `.ts` file.

```ts
import { check } from "kiira-core"

const result = await check({ cwd: process.cwd() })

console.log(result.stats.errors)
```

It takes these options:

| Option | Description |
| --- | --- |
| `cwd` | The directory to run in. |
| `files` | Markdown files to check, relative to `cwd`. Defaults to the config's `include`. |
| `config` | A config object, used as is. When you leave it out, Kiira loads the config file from `cwd`. |
| `plugins` | Plugins added to the config's `plugins`. A plugin with the same `name` as one in the config replaces it. |

The result has the same `stats` and `diagnostics` as the [JSON reporter](/latest/cli/reporters#json), except that positions are zero-based. Document, program and project rules all run.

## Passing a plugin inline

Pass a plugin without putting it in a config file. Set its rule levels in `rules`, or rely on the rule's default level.

```ts
import { check } from "kiira-core"
import { definePlugin, defineRule } from "kiira-core/plugin"

const noTodo = defineRule({
  meta: { scope: "document", defaultSeverity: "error" },
  create(ctx) {
    ctx.text.split("\n").forEach((line, index) => {
      const character = line.indexOf("TODO")
      if (character === -1) return
      const start = { line: index, character }
      const end = { line: index, character: character + 4 }
      ctx.report({ range: { start, end }, message: "Remove TODO before publishing." })
    })
  },
})

const result = await check({
  cwd: process.cwd(),
  plugins: [definePlugin({ name: "docs", rules: { "no-todo": noTodo } })],
})

for (const diagnostic of result.diagnostics) {
  console.log(diagnostic.markdownFile, diagnostic.code, diagnostic.message)
}
```

See [Rules](/latest/configuration/rules) for what a rule can do.
